# Restore positive-signal routing and silent Root-only continuation

Implicit routing uses strong positive task-shape signals, clear exclusions, and directional tie-breakers. Read-heavy exploration, code-plus-docs verification, independent evidence, specialist review, and context reduction lean toward one bounded Child Contribution. Trivial, ambiguous, strongly sequential, duplicative, and overlapping-write work stays in Root. Boundedness, autonomy, and ownership remain dispatch safeguards, but no longer form an all-conditions-must-pass benefit checklist.

Every `ROOT_ONLY` result is silent. Only eligible work emits the policy-specific routing receipt before dispatch. A silent Root-only decision may be reconsidered once when clarification or lightweight read-only discovery materially changes the task shape before implementation.

This supersedes ADR-0013's ordinary Root-only receipt and ADR-0014's conjunctive implicit threshold. It preserves the two-Hook architecture, one-Child-plus-Root workflow, Native capability check, Leaf Child, Child Reuse, Write Ownership, Root integration, and eligible receipt templates.
