# Select the subagent execution backend by runtime capability

Cast Subagents will preserve each Bundled Subagent's Static Model Mapping through one of two Execution Backends. Every Bundled Subagent TOML enables `web_search = "live"`; this exposes live search without requiring a role to use it. After Dispatch Authorization, the Root Session performs a Backend Capability Check against the visible `spawn_agent` interface. When custom agent, model, and reasoning selectors are exposed, it uses the Native Subagent Backend. When those selectors are absent, it uses the CLI Worker Backend. That backend uses one stateless Python 3.11+ CLI Worker Runner invocation per selected role. The runner uses the standard-library `tomllib` module to read `${CODEX_HOME:-$HOME/.codex}/agents/<role>.toml`, accepts the delegated handoff on stdin, and starts one independent ephemeral `codex exec` process. It builds an argv array without shell quoting: global flags include `-a never`, `--search`, `--disable multi_agent`, and `--disable multi_agent_v2`; exec flags include `--ephemeral`, the role's explicit model, reasoning effort, and sandbox, the workspace `-C` path, optional `--add-dir` paths, and `-` for stdin. The role's developer instructions and delegated handoff form the stdin prompt. The runner retains user config, MCP, and authentication; it does not use `--ignore-user-config` or `--dangerously-bypass-approvals-and-sandbox`. It returns the worker's stdout and exit status directly to the Root Session, adding stderr on failure; it creates no temporary output file or additional result protocol. `multi_agent_v2` is an under-development feature name, so an unsupported or renamed flag must fail the worker visibly rather than being silently omitted. The Root Session may invoke multiple runners concurrently; the runner contains no lineup orchestration, queue, daemon, persistent session, log directory, or third-party dependency. Each worker uses the role's `sandbox_mode` with `-a never`; it never bypasses approvals or sandboxing. Permission failures are returned to the Root Session instead of prompting inside the non-interactive worker. Every worker is a leaf: its prompt contains `delegation_context: delegated-subagent`, forbids further delegation, and the runner disables both `multi_agent` and `multi_agent_v2` while retaining the rest of the user's Codex configuration. Selection is based on exposed capability rather than the parent model name or a Codex version allowlist, so restored native support automatically becomes preferred without a plugin update. CLI Worker Backend is a compatibility backend, not a model downgrade; AGENTS.md injection is not restored, and Delegation Gate Activation remains hook-only. Release validation includes automated argument and failure-propagation checks, an isolated plugin install, and one real ephemeral CLI worker for each of the Terra, Luna, and Sol model families because their exact account availability is not guaranteed by the public model documentation.
